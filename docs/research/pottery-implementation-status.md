# 도자기 시범: 구현·검증 상태

2026-10-18 로컬 작업. 원격 반영·서비스 배포 없음.

## 완료

- 전국 수집·지역 필터 범위 확정. 초기 지역별 조사 및 부분 검토 후보 JSON 작성.
- 테스트로 청자 등 일반 도자 용어의 백자 오분류, 질문만으로 가족·혼자·분위기 적합성을 단정하는 오류 재현: 신규 12개 중 수정 전 11개 실패.
- 청자·도예·도자기·사기장·달항아리를 백자로 단정하는 매핑 제거. 도자기 공통 태그 사용. 청자·분청 전용 검색은 아직 미구현.
- 추천 이유를 등록된 분야 안내로 제한. 질문만으로 속성을 생성하는 규칙 제거.
- 추천 생성 지침에 미제공 참여 조건·자격·예약 가능 여부 추정 금지 추가. 생성 오류·빈 응답의 최적 추천 단정 문구 제거.
- 수정 후 전체 단위 테스트 77개 통과, diff 공백 검사 통과. 생성 지침 변경의 실제 LLM 준수율은 측정하지 않음.

## 현재 실행 제약

- 설정된 모델 키·내부 키는 존재. 값은 노출하지 않음.
- 최초 설정은 원격 Supabase였으며 연결 실패. 이후 사용자 요청으로 기존 Docker PostgreSQL·Redis를 시작하고 로컬 DB 주소를 프로세스 환경변수로 지정해 Python `SELECT 1` 연결 성공. 원격 `.env`는 변경하지 않음.
- 최초 로컬 데이터 0건 확인 후 누락 AI 청크·임베딩 이력 테이블과 인덱스 준비 완료. 로컬 전용 가상 장인 1명, 체험·문화 항목·청크 각각 2건 적재. 공식 자료는 앱 예약 상품으로 적재하지 않음. [로컬 접속 방법](../local-docker-db.md) 참조.
- 합성 단위 벡터로 실제 PostgreSQL 검색을 실행해 청자 항목·체험이 우선 반환되는 경로 확인. 의미 검색 품질 검증이 아님.
- 최초 실제 임베딩 호출은 `AuthenticationError`로 실패했으나, 사용자가 키를 갱신한 뒤 재실행 성공. 실제 제공자 임베딩으로 합성 데이터를 갱신하고 문화·체험 검색의 청자 우선 반환, 비어 있지 않은 LLM 답변과 출처 2건 반환을 확인. 실제 장인 데이터의 추천 정확도나 생성 문장별 사실성을 검증한 것은 아님.
- 실제 DB 검색 및 모델 답변의 개선 전후 비교는 미실행. 단위 테스트를 추천 품질 검증으로 대체하지 않음.

## 다음 구현 단위

### 후속 실행 결과

- 지역·최대 등록 가격·최대 소요시간·정원 SQL 필터 구현, Spring 요청 전달 완료.
- 검토 상태와 직접 실습 여부를 갖는 `experience_culture_links` 모델·후속 마이그레이션 추가. 로컬 보완 도구로 누락 테이블 생성. 문화 항목 또는 기술을 명시한 요청은 검토된 직접 실습 관계로 제한.
- 연결 근거 및 실제 적용 필터를 Python과 Spring 응답에 추가. 기존 기본 응답 필드와 생성자 호환 유지.
- 자유문장 지역·예산의 제한적 패턴 추출. 모호한 예산은 무시하지 않고 확인 안내.
- Python 90개 테스트, 실제 PostgreSQL 합성 조건·관계 검증 15개 통과. 실제 모델·DB·HTTP API 조건 검색 점검 성공.
- 요청에 조건이 있는데 AI 장애 시 기본 체험으로 임의 대체하는 경로를 제한. Spring 추천 테스트 13개 통과 확인.
- 부안·양구·제주 및 파주 후보까지 조사 경로 확장. 실제 운영자·장인과 최신 자격의 확인은 완료되지 않음.
- 상세 계약·검증 한계는 [조건 검색 계약](pottery-filter-contract.md) 참고.

아래는 전체 설계 순서이며 위 결과로 일부 구현 완료했다. 남은 작업은 실제 장인과 체험의 관계 검토, 프론트 필터·근거 표시, 날짜·잔여석 연동 및 실데이터 평가다.

1. 기존 DB를 안전하게 시작하거나 접근 가능한 DB 설정 확보 후 읽기 전용으로 실제 문화·장인·체험·일정 데이터 목록 확인. 기존 데이터와 외부 조사 후보의 중복을 검토.
2. 평가 질문에 실제 ID와 기대 후보를 연결. 현 버전 응답을 기록하되 외부 자료만 존재하는 상품을 앱 예약 후보로 처리하지 않음.
3. 기술·유형 관계 모델 추가:
   - `pottery_type`: 청자·백자·분청 등, `technique`: 상감 등, `activity`: 물레·손빚기·채색 등 서로 구분.
   - 기존 `experiences.artisan_id`는 재사용.
   - 체험–기술 관계에 근거 URL·확인일·검토 상태·직접 실습/문화적 연관 구분.
   - 외부 후보는 사용자 계정이 필수인 기존 장인 테이블에 억지로 생성하지 않음.
4. Spring–Python 계약을 확장해 지역·가격·시간·언어를 전달하고 필수 조건 필터 적용. 예약 가능 여부는 Spring 일정·예약 로직으로 확인.
5. 문화 출처와 추천 체험의 연결 근거를 응답에서 별도 반환. 기존 answer/sources/IDs 필드는 호환 유지.
6. 동일 질문으로 필수 조건 위반·허위 속성·잘못된 ID·검색 관련성 및 응답시간 평가. 결과가 나온 뒤 README 성과 갱신.

## 남은 조사

- 현재까지 전국 조사를 완료한 것이 아님. 초기 경기·강진·문경·김해 경로 외 지역은 추가 탐색 필요.
- 공식 공방의 개별 프로그램, 장인 직접 진행, 소성·배송·수령 조건 확인이 가장 큰 공백.
- 최신 공식 자격과 공고 당시 자격을 분리해 관리.
- 자료 이용조건 확인 전 원문 대량 임베딩 적재를 진행하지 않음.
